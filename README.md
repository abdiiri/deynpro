# DeynPro — Shop Management (Web)

Customers, debts, sales, and inventory for small shops. This is the
web/PWA build: it runs in any modern browser, on any device (phone,
tablet, laptop), installs as an app from the browser ("Add to Home
Screen" / "Install"), and works fully offline after first load.

A separate Electron build of the same codebase (`electron/`, `npm run
dist`) produces a Windows desktop installer with a local SQLite
database — that build is unaffected by anything below.

## How data storage works

The app talks to a single interface (`src/lib/db.ts`) that picks the
right backend automatically:

- **Desktop app (Electron):** SQLite via IPC (`window.electronDB`).
- **Browser / installed PWA, any device:** IndexedDB, implemented in
  `src/lib/webDB.ts` — same tables, same soft-delete behavior, same
  stock triggers. No server, no account, no setup required.

Data in the web build lives in that browser's IndexedDB storage —
it's private to each device/browser, persists across restarts, and
isn't wiped by normal browsing. It is **not** synced between devices.
If you want the same data to show up on every device (e.g. a phone at
the counter and a laptop in the back office), swap `webDB.ts` for a
hosted Postgres backend (Supabase is the easiest — the codebase used
to have a Supabase integration, in `src/integrations/supabase/`, that
can be revived) and it becomes real multi-device sync.

## License codes

The `DPL1.…` activation codes generated by `license-admin/` work
unchanged on the web build too — `src/lib/webLicense.ts` verifies the
same signature locally in the browser (Web Crypto, Ed25519), no
network call. Keep `license-admin/private.pem` off any public repo;
it's the private key that signs new codes.

### Device limits (optional)

Each code now carries a device limit (default 2 — e.g. one phone + one
computer). The check happens once, at the moment a code is entered on
a *new* device — that's the only time this app talks to the network
for licensing; day-to-day use stays fully offline. Set it up:

1. Create a free project at supabase.com.
2. In its SQL Editor, run `license-admin/supabase/schema.sql`.
3. Copy the Project URL and the publishable key (Project Settings →
   API) into `.env` (copy from `.env.example`) as `VITE_SUPABASE_URL`
   and `VITE_SUPABASE_PUBLISHABLE_KEY` — and add the same two as environment
   variables in the Vercel project settings.
4. In `license-admin/`, copy `supabase-config.example.json` to
   `supabase-config.json` and fill in the same URL plus the secret
   key (same page, further down — keep this one private, it bypasses
   the device limit entirely). The admin panel then shows how many
   devices each shop is using and lets you reset them.

Without steps 3–4, the app still works exactly as before — no device
limit is enforced, same as if this feature didn't exist.

## Local development

\`\`\`bash
npm install
npm run dev
\`\`\`

## Deploying to Vercel

\`\`\`bash
npm install
npm run build   # outputs to dist/
\`\`\`

Or just import the GitHub repo in Vercel — `vercel.json` already sets
the framework, build command, and output directory, so no
configuration is needed in the dashboard.

## Rebuilding the desktop app

The web `package.json` no longer lists the Electron-only packages
(`electron`, `electron-builder`, `better-sqlite3`, `electron-store`,
`electron-updater`, `electron-pos-printer`) so that `npm install` on
Vercel stays fast. To build the desktop installer again:

\`\`\`bash
npm install --save-dev electron electron-builder @electron/packager
npm install --save better-sqlite3 electron-store electron-updater electron-pos-printer
npm run dist
\`\`\`
